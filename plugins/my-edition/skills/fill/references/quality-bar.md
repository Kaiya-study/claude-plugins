# 品質基準 — 「読者が自分で検証できる粒度」

## なぜこの基準なのか

目標は「正しい」ではなく「**検証できる**」である。

「正しい」は読者に確かめようがない。確かめられない正しさは、信じるか信じないかの話になる。
「検証できる」なら、読者は自分の手で確かめられる。**読者が最終の検証層になる。**

そして逆説的だが、**検証できるように書くと、書き手は自分の誤りを隠せなくなる**。
曖昧に書けば誤りは隠れる。ステップを分けて根拠を書けば、誤りは露出する。それが狙いである。

読者が検証しようとして詰まれば質問が出る。その過程で誤りも見つかる。
検証可能に書かれていなければ、読者は「よく分からないがそういうものか」で流し、
誤りは永久に見つからない。

## 4つの条件

### 1. 1ステップ1操作

「両辺を微分して部分積分した」を一行で済ませない。読者が一つずつ確認できる粒度に割る。

**悪い例**

> 部分積分により (3.7) を得る。

**良い例**

> 積 `u v'` の形に見て、`u = e^{-ax}`、`v' = 1` と取る。部分積分の公式から
> ```
> \int_0^\infty e^{-ax}dx = \Big[ x e^{-ax} \Big]_0^\infty + a\int_0^\infty x e^{-ax} dx
> ```
> 第1項は `x → ∞` で `e^{-ax}` が勝つので 0、`x = 0` でも 0。よって第1項は消える。

### 2. 根拠の明示

どの規則・定理・既出の式を使ったかを必ず書く。

- 「(1.7) より」
- 「Tonelli の定理により（被積分関数が非負なので使える）」
- 「指数法則」
- 「両辺は連続なので、極限と積分を交換してよい」

根拠が書いてあれば、読者は**自分がその規則を知っているかを確認できる**。
知らなければ、そこが質問になる。これが正しい詰まり方である。

### 3. 飛躍の自己申告

埋めきれない箇所は、黙って飛ばさずに宣言する。

> ここは天下り的で、なぜこの置換を思いつくのかは本書では説明されない。結果から逆算すると
> `u = r^2` が効くことは分かるが、動機づけは第5章の変数変換の一般論まで待つ必要がある。

読者は「ここは検証できない」と分かる。黙って飛ばされるより遥かによい。

### 4. 検算の手がかり

読者が自分で確かめる道具を渡す。

- 「a = 1 とすれば (2.8) に一致する」
- 「次元解析で確かめられる」
- 「r → ∞ の極限で 0 になるはず」
- 「n = 1 を代入すると、前節の結果と合う」

これがあると、読者は受け身の読解から検算という能動的作業に移る。

## 検証可能ラインはプロファイルで決まる

**同じ行間でも、検証可能なラインは人によって違う。**

- ヤコビアンを知っている読者 → 「ヤコビアンより `dx dy = r dr dθ`」で検証できる
- 知らない読者 → 行列式を書き下さないと検証できない

だからプロファイルの役割は「どこまで親切にするか（親切の度合い）」ではなく、
「**どこまで書けばこの読者が検証できるか**（品質基準）」である。

## 学習効果について

「AIに行間を埋めてもらう」は受動的に聞こえるが、実際は逆である。
**検証という能動的な作業に変換されている。**

挫折の原因だった「計算が追えない」は消えるが、思考は残る。
むしろ「読んで分かった気になる」より能動的である。

## 分量の目安

1つの補完は、原則として**画面1つに収まる長さ**にする。長くなるのは、たいてい
複数の行間が混ざっているからで、その場合は分ける。

ただし「未習」項目の補完は長くてよい。定義から書く必要があるため。
