# マイ教科書として組む

**作るのは注釈集ではなく、本そのものである。**本文が丸ごと入っていて、その読者のレベルに
合わせて行間が補完されている。参考書を開かなくても、これだけで読み切れる状態にする。

着手前に読む。

- `${CLAUDE_PLUGIN_ROOT}/shared/state-format.md`
- `references/markup.md` — **出力するHTMLの構造。必読**
- `assets/template.html` — 外枠（CSS・JavaScript込み）

MathJax はここには入っていない。初回の組版で一度だけ取得する（後述）。

## 手順1 — 材料を集める

- `.my-edition/text/<unit-id>.md` — 本文（原文どおり）
- `.my-edition/gaps/<unit-id>.md` — 補完
- `.my-edition/ledger.md` — 式と記号
- `state.json` — 章構成、どの単位が `filled` か

`status: filled` の単位をすべて対象にする。`built` のものも含めて組み直してよい
（追記型なので、既存の出力は上書きされる）。

## 手順2 — 本文を組む

`references/markup.md` の構造に従う。要点。

- **本文が主役。**読書のための組版にする
- **補完は本文の流れに置くが、地色を変えて区別する。**原文と混ざってはいけない
- 補完は式に付随させ、既定では畳んでおく。「途中式をひらく」で開く
- **行間に番号を振って列挙しない。**それは注釈集の書き方である

## 手順3 — 台帳から自動的に出るものを組み込む

ここが市販の電子書籍にできないところで、**台帳があるので追加作業なしに手に入る**。

- **式番号のリンク化** — 本文や補完に現れる式番号を、その式へのリンクにする。
  クリックでジャンプ、ホバーで式そのものをポップアップ（読書が途切れない）
- **逆引き** — 各式に「この式を使う式」を表示する。先の展開が見える。
  `ledger.md` の `使用先` から作る
- **原著モード** — 補完を一括で畳み、原著の記述だけを読めるようにする。
  「本が何と書いたか」と「補ったもの」の区別を、読者がいつでも確認できる

## 手順4 — プロファイルを見せる

サイドバーに、この版が生成されたときのプロファイルを表示する。
「既知の項目には行間を作っていません」と添える。

読者のレベルが変われば同じ本から別の版が生成される、ということが1画面で伝わる。

## 手順5 — 断片だけを書く（2MB を自分で書き出さない）

**MathJax 本体をモデルが書き出してはいけない。**出力の約95%は MathJax で、
自分が作っているのは残りの3%（本文と補完）にすぎない。ここを毎回書くと、
1まとまり進めるたびに2MB超を書き直すことになり、極端に遅くなる。

自分が書くのは `parts/` の断片だけ。

```
.my-edition/
├── b64/              ← 図の base64。1図1ファイル・1行
│   └── p026_fig1.txt
└── parts/
    ├── title.txt     ← 書名を1行。記号（' < > &）は使わない
    ├── rail.html     ← サイドバー。テンプレートの <!-- RAIL --> に入る
    ├── ch01.html     ← 本文だけ。<!-- CONTENT --> に順に入る
    ├── ch02.html
    └── colophon.html ← 巻末。いちばん最後に入る
```

- **`rail.html` は章が増えるたびに作り直す。**目次は本全体のものになる（数KB）
- **`chNN.html` は本文の断片だけ。**`<html>` も `<head>` も `<main>` も書かない。
  中身は `references/markup.md` の「全体」以降の構造そのまま
- **巻末は `colophon.html` に分ける。章の断片に書かない。**
  章ごとに書くと、章を足したときに前の章の巻末が本の途中に残る。
  **章を足すたびに上書きし、いまの到達点だけを書く**
- **図の base64 は断片に直接書かない。**`b64/` に置き、
  `src="data:image/png;base64,{{FILE:.my-edition/b64/p026_fig1.txt}}"` の形で参照する。
  直接書くと**図のぶんを毎回書き直すことになる**（章ひとつ70KBが900KBに膨らんだ実例がある）
- **章の完成を待たない。1まとまり終わるごとに `chNN.html` に足して、手順6 を走らせる**
- 目次には未作成の節もグレーで並べる。育っていく途中だと分かるように

読者は最初の1まとまり（1時間弱）で手に取れるものを得る。以降の待ち時間が
「何も無い時間」ではなく「もう動いているものが育つ時間」になる。

## 手順6 — 連結はコマンドに任せる

**既定は、全章を1ファイルにまとめる。**

```
.my-edition/out/book.html   ← 読者が開くのはこれだけ
```

まとめる理由は2つ。**章をまたいだ式番号のリンクと逆引きが成立すること**（台帳は本全体で
ひとつなので、出力が章で切れていると先の展開が見えない）。もうひとつは、MathJax の
約2.1MB が章ごとに重複しないこと（10章なら 22MB が 2.9MB になる）。

macOS / Linux:

```
sh "${CLAUDE_PLUGIN_ROOT}/skills/build/assets/assemble.sh" \
   "${CLAUDE_PLUGIN_ROOT}/skills/build/assets/template.html" \
   .my-edition/parts/title.txt .my-edition/parts/rail.html \
   .my-edition/assets/tex-svg.js .my-edition/out/book.html \
   .my-edition/parts/ch01.html .my-edition/parts/ch02.html .my-edition/parts/colophon.html
```

Windows:

```
powershell -NoProfile -ExecutionPolicy Bypass -File "${CLAUDE_PLUGIN_ROOT}/skills/build/assets/assemble.ps1" "${CLAUDE_PLUGIN_ROOT}/skills/build/assets/template.html" .my-edition/parts/title.txt .my-edition/parts/rail.html .my-edition/assets/tex-svg.js .my-edition/out/book.html .my-edition/parts/ch01.html .my-edition/parts/ch02.html .my-edition/parts/colophon.html
```

**断片は章の順に並べて渡し、`colophon.html` を最後に置く。**並べた順がそのまま本の順になる。
巻末を最後にしないと、本の途中に「ここまで生成済み」が現れる
（コマンドが警告を出すが、順序を直すのはこちらの仕事）。

- **`-ExecutionPolicy Bypass` を省かない。**既定の設定では `.ps1` の実行が拒否される
- **MathJax を渡す位置に `-` を書くと軽量版になる**（CDN 参照のまま・約100KB）。
  取得できなかったときと、「軽くして」と頼まれたときはこれを使う

### 章ごとに分けるのは、言われたときだけ

読者が「重い」「章ごとに分けて」と言った場合に限り、断片を1つずつ渡して
`out/ch01.html` `out/ch02.html` … を作る。

**分けると、他の章の式へは飛べなくなる。**目次からも移動できない。
そのことを伝えたうえで分ける。**黙って分けない。**

## 手順7 — 状態を更新して渡す

`state.json` の当該単位を `built` にする。出力先のパスを読者に伝える。

## 出力の注意

- **単一ファイルにする。**CSS・JavaScript はすべてインラインに含める。持ち運べることが要件
- **既定はオフラインで読める版。**完成品は約2.2MB になるが、章がいくつ増えても
  MathJax のぶん（約2.1MB）は増えない。ネットのない場所で読めることが要件なので、これを既定とする。
  **埋め込みは手順6 のコマンドがやる。自分で書き出さない**
- **MathJax はプラグインに同梱していない。初回だけ取得する**（次項）
- **MathJax 本体に無いコマンドを本文に出さない**（`\boldsymbol` など）。取りに行って失敗し、
  **ページの数式が1つも出なくなる。**一覧と代替は `references/markup.md`
- 数式は MathJax の SVG 出力を使う（外部フォントを取りに行かないため、オフラインでも崩れにくい）
- ダークモードに対応する。テンプレートに含まれている
- 巻末に、原本の書誌と「配布しない」旨の注記を必ず入れる

## MathJax の取得（初回だけ）

**プラグインには同梱していない。**Apache-2.0 のライブラリを再配布しないため。
その代わり、**最初の組版のときに一度だけ落として、以後は使い回す。**

置き場所は `.my-edition/assets/tex-svg.js`。

```
https://cdnjs.cloudflare.com/ajax/libs/mathjax/3.2.2/es5/tex-svg.js
```

- **バージョンを固定する。**`latest` を取らない。テンプレートの `src` と同じ 3.2.2 を使う。
  版が変わると、いつ作ったかで出力が変わる
- すでに `.my-edition/assets/tex-svg.js` があれば**取りに行かない**。まとまりごとに落とさない
- 取得できなかったときは、**軽量版（テンプレートのまま）で出力して、その旨を読者に伝える。**
  組版そのものは止めない。テンプレートには CDN へのフォールバックと、
  数式が出なかったときの通知が仕込んである
- 落としたものを出力に埋め込む。**これをやめるとオフラインで読めなくなる**ので、
  「単一ファイル・オフライン」という要件が崩れる

## やってはいけないこと

- **原著の注釈をまとめる／落とす。**同じマーカーでも、ページが違えば別の注釈である。
  `text/` にある数と出力の数を突き合わせる（`references/markup.md` の「注釈」）
- **MathJax 本体を自分で書き出す。**手順6 のコマンドに任せる。
  2MB を書くと1まとまりごとに極端に遅くなる
- **`out/` の完成品を直接編集する。**直すのは `parts/` のほうで、`out/` は作り直す
- 本文を要約する、章立てを組み替える
- 補完を本文に溶け込ませて区別を消す
- 完成品を複数ファイルに分割する（CSSやJSを外に出す）。`parts/` は途中経過なので別
- 生成したマイ教科書を配布可能な形で扱う。**これは自分で買った本から自分用に作るもの**であり、
  本文を含む成果物を他人に渡してはいけない
