# マイ教科書づくりの入口

**利用者に工程を意識させない。**「作って」と言われたら、状態を見て次にやるべきことを判断し、
そこまで進めて報告する。工程名（setup / ocr / fill / build）を利用者に説明しない。

## 先に — これは通しの作業用

**画像を1〜2枚だけ渡された依頼は、ここではなく page が受ける。**準備も状態ファイルも要らず、
数分で返せるため。フォルダを対象にした依頼、あるいは既に `.my-edition/` がある本の続きだけ、
この手順で進める。

## 手順1 — 場所を確かめる

作業対象のフォルダを決める。優先順は次のとおり。

1. 利用者がフォルダを指定した
2. カレントディレクトリにスキャン画像（連番の画像ファイル）がある、またはその直下のフォルダにある
3. どちらでもなければ**聞く** — 「参考書のスキャン画像はどこにありますか」

**画像より先に、本文データがないかを見る。**LaTeX ソース（`.tex`）、文字起こし済みの
Markdown やテキスト、テキスト層のあるPDFがあれば、**スキャンと取り込みを飛ばせる。**
いちばん重い工程が丸ごと消えるので、ここを見落とすと無駄が大きい。

見つかったら確認する。

> `src/` に LaTeX ソースがあります。これを本文として使いますか。
> 使う場合、スキャンと文字起こしは飛ばして、そのまま行間埋めに進めます。

扱いは `${CLAUDE_PLUGIN_ROOT}/shared/state-format.md` の「本文データが手元にある場合」。

画像も本文データも見つからないときは、それを伝えて止まる。勝手に探し回らない。

## 手順2 — どこまで終わっているかを見る

`<フォルダ>/.my-edition/state.json` を読む。仕様は `${CLAUDE_PLUGIN_ROOT}/shared/state-format.md`。

| 状態 | 次にやること |
|---|---|
| `.my-edition/` がない | **準備**（手順3-A） |
| 全単位が `pending` | 読みたい章を聞いてから**取り込み** |
| 対象単位が `pending` | **取り込み**。ただし `textFrom` が `provided` なら飛ばして行間埋めへ |
| 対象単位が `ocr` / `checked` | **行間埋め** |
| 対象単位が `filled` | **組版** |
| 対象単位が `built` | 次の単位へ。章が終わっていれば次章を聞く |

**必ず state.json から判断する。**会話の記憶に頼らない。この作業は数日から数週間にわたり、
毎回まっさらな状態で始まる。

## 手順3 — 該当する工程を実行する

それぞれの手順書を**読んでから**、そのとおりに実行する。ここに要約を書き写さない。

- **A. 準備** — `${CLAUDE_PLUGIN_ROOT}/skills/setup/SKILL.md`
- **B. 取り込み** — `${CLAUDE_PLUGIN_ROOT}/skills/ocr/SKILL.md`
- **C. 行間埋め** — `${CLAUDE_PLUGIN_ROOT}/skills/fill/SKILL.md`
- **D. 組版** — `${CLAUDE_PLUGIN_ROOT}/skills/build/SKILL.md`

## 手順4 — 1まとまり進めたら、止まって報告する

**章の完成を待たない。**12ページ分の取り込み・行間埋め・組版が終わったら、そこで一度止まる。

報告に含めるもの。

- 出力されたHTMLの場所（**これが利用者の成果物**。最初にこれを言う）
- 何ページ分が入ったか、いま章のどのあたりか
- 判断を仰ぎたいこと（判読不能だった箇所、台帳になかった参照など）があれば、それ

そのうえで「続けますか」と聞く。**黙って次のまとまりに進まない。**
利用者が「最後まで」と言った場合は、上限に当たるまで続けてよい。

## 補完について質問されたら、記録する

**利用者の質問は、行間の粒度に対する唯一の証拠である。**答えて終わりにしない。

生成したHTMLの「この説明について聞く」から来た質問も、口頭での質問も、同じ扱い。

- **詳しく質問された** → その書き方ではまだ行間が広い。同じ種類を細かく割る
- **「ここまで丁寧でなくてよい」と言われた** → そこは行間ではなかった。同じ種類を広げる

答えたあとに、`profile.md` の「粒度の調整」へ**きっかけと一緒に**書く
（書式は `${CLAUDE_PLUGIN_ROOT}/skills/setup/references/profile-questions.md` の「更新」）。
範囲が判断できないときは聞く。「同じような式変形も、すべて細かくしますか」

**質問が来ないことを理由に、行間を広げてはいけない。**
沈黙は「分かっている」ではなく、「まだ読んでいない」かもしれない。
粗くしてよいのは、利用者が明示的にそう言ったときだけ。

## 手順5 — 上限を見張る

`usage.unitsThisSession` が3に近づいたら伝える。

> このセッションで2まとまり進みました。あと1つで利用上限に当たる見込みです。ここで区切りますか？

章をいくつか終えて**週の上限に近づいている**ときだけ、次を案内する。**先回りして勧めない。**

> 1冊を通してやると、この構成では2週間前後かかります。
> 文字起こしだけを外部のOCR（Gemini API など）に移すと2〜3日に縮みます。設定は10分ほどです。

## 最初の一回だけ、期待値を伝える

`.my-edition/` がなく、これから準備を始めるときに限り、次を短く伝える。毎回言わない。

- 12ページずつ進み、**1まとまりごとに読めるHTMLが出る**。章の完成を待たなくてよい
- 最初の1まとまりは**1時間かからず、追加費用もかからない**
- 厚い章は途中で利用上限に当たり、待ちが入ることがある
- 一番読みたい章を選べばよい。薄い章を探す必要はない

## 態度

- **工程名を言わない。**「OCRを実行します」ではなく「12ページ分を読み込みます」
- 状態ファイルの名前やパスを説明しない。聞かれたら答える
- 判断が要るときは止まって聞く。特に、原文が読み取れない箇所と、台帳にない式への参照。
  **推測で進めない**
